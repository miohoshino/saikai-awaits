## 0. Claude Code への作業ルール（最優先）

1. **この仕様書と矛盾する実装はしない。** 矛盾や不明点を見つけたら、コードを書く前に質問すること。
2. **「7. 未決事項」に挙げた項目は勝手に決めない。** 必要になったら、選択肢を示して質問すること。
3. 依頼者（星野）はコーディング経験が少ない。説明は専門用語を避け、「誰が・どの画面で・何ができるようになるか」で書くこと。
4. **1回の修正は1つの機能に絞る。** 修正前に計画を出し、承認を得てから変更すること。
5. 修正のたびに、依頼者がブラウザで確認できる手順（どの画面を開いて、何を押せば、何が見えるか）を書くこと。
6. 個人情報に関わる変更では、必ず「この変更で、誰に何が見えるようになるか（見えなくなるか）」を説明すること。
7. 既存のデータを消したり、作り直したりする変更は、必ず事前に確認を取ること。

## 1. コンセプト

- SAIKAI AWAITS は、西海市民のための**「つながりの入口」**。中身は**タウンページ（名簿）**。
- Linktree のように**入口に徹する**。本物のコミュニティは、その後ろ（LINE、Instagram、実際の活動場所など）にある。
- **主役はクラブ**（サークル、教室、地区の集まりなど）。西海市にはクラブの一覧がないため、それ自体がこのアプリの価値になる。
- 人は「似た人」「共通点」で**見つける**ためのもの。**会うのはクラブを通して**。
- **このサイトは連絡用ではない。** アプリ内のチャット、メッセージ、投稿、タイムライン、いいね等は作らない。
- 仕事以外の属性（犬を飼っている、元野球部、沖縄に住んでいた、お酒好き等）で人とクラブがつながる。
- 個人による仕事・営業目的の利用は禁止。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 利用者 | ログインできる人（招待された人） |
| 大人 / 未成年 | 18歳以上 / 18歳未満。未成年には「未成年マーク」が付く |
| クラブ | サークル、教室、地区の集まり、お店主催の会など。有料のものも含む |
| クラブ管理者 | そのクラブの情報を編集できる利用者。クラブを作った人が最初の管理者になる |
| 運営 | SCC の運営担当。監査と管理画面の操作を行う |
| 属性タグ | 仕事以外の特徴（例：犬を飼っている、元野球部） |
| 出没スポット | よくいる場所。地区単位、または自由入力の具体的な場所 |

## 3. 利用者と、見えるもの

### 3-1. 登録・ログイン
- **招待制。** ログインしていない人は、トップページ以外の中身を一切見られない。
- 招待の具体的な仕組みは**未決**（7章）。当面は現在のログイン方式を維持し、後から招待の仕組みを追加できる作りにしておく。

### 3-2. 公開範囲
- ログインした利用者は、**全員のプロフィールと全クラブ**を見られる（未成年の例外は5章）。
- 公開範囲を利用者ごとに細かく設定する機能は作らない。

## 4. 機能仕様

### 4-1. クラブ（主役）

**クラブページの項目**

| 項目 | 必須 | 備考 |
|---|---|---|
| 名前 | 必須 | |
| 活動内容 | 必須 | 文章 |
| 活動している地区 | 必須 | 地区の一覧から選ぶ |
| 活動場所 | 任意 | 公民館、体育館など |
| 頻度 | 任意 | 「毎週土曜」「月1回」など自由入力 |
| 連絡・参加の方法 | 必須 | 外部リンク（LINEオープンチャット、Instagram等）、電話、「直接来てOK」等の文章。**複数登録できる** |
| 有料かどうか | 必須 | 有料なら「有料」表示を出す |
| 未成年参加可 | 必須 | はい / いいえ |
| 管理者 | 自動 | 作成者が最初の管理者。未成年も管理者になれる |
| 最終更新日 | 自動 | 画面に表示する |

**クラブの登録**
- **利用者なら誰でも作れる。** 作成直後から公開される。
- 登録画面に次の注意を必ず表示する：
  「登録内容は運営が確認します。不適切な内容は削除される場合があります。」
- 連絡・参加の方法のリンクは、管理者がいつでも簡単に差し替えられること（プラットフォームは変わるため）。
- 「連絡・参加の方法」は**クラブのアカウント**（クラブ用のLINE、Instagram等）であり、管理者個人のプロフィールとは結びつけない。個人の連絡先を入れるかどうかは管理者が自分で判断する。

**クラブ一覧・検索**
- トップ画面（ログイン後）はクラブ中心：近くのクラブ（自分の地区）、おすすめのクラブなどを並べる。
- 地区、活動内容のキーワード、有料/無料、未成年参加可で絞り込める。

**所属**
- 利用者はクラブに「所属」を登録できる。
- 所属は**隠せない**（クラブページのメンバー一覧と、本人のプロフィールに表示される）。

### 4-2. プロフィール（人）

| 項目 | 必須 | 備考 |
|---|---|---|
| 表示名 | 必須 | 実名・ニックネームどちらでも可（未成年はニックネームのみ） |
| 住んでいる地区 | 必須 | 地区の一覧から選ぶ |
| 属性タグ | 任意 | 用意されたタグから選ぶ＋自由入力で新しいタグを追加できる |
| 出没スポット | 任意 | 下記参照。**未成年は入力不可** |
| 所属クラブ | 自動 | 4-1 の所属から表示 |
| 連絡先 | 任意 | LINE ID、Instagram 等。**未成年は入力不可** |
| 自己紹介 | 任意 | 短い文章 |

**出没スポット**
- 基本は**地区単位**で選ぶ。
- 本人が望めば、具体的な場所（お店の名前、「〇〇港の釣りポイント」等）を自由に入力できる。
- **曜日・時間を入力する欄は作らない。**
- 具体的な場所を入力するときに、注意を表示する：
  「ここに書いた場所は、ログインしている全員に見えます。」

**属性タグ**
- 運営があらかじめ用意したタグから選べる。
- 自由入力で新しいタグを追加できる。追加したタグは他の人も選べるようになる。
- 表記ゆれ対策（「犬」と「いぬ」をまとめる等）は**今回は行わない**。

### 4-3. 似た人・おすすめ・近い場所
- **似た人**：次の2つで判断する。
  1. 同じ属性タグが多い人
  2. 同じクラブに所属している人
- **近い場所**：クラブの活動地区・活動場所、人の地区・出没スポットで探す。
- 「元野球部が12人います」のように、**共通点の人数**が見えると望ましい。
- 未成年の扱いは5章に従う。

### 4-4. マインドマップ（見える化）
- 人とクラブの関係を、マインドマップ形式で見せる。
- クラブ所属は隠せない。
- 未成年をマインドマップにどう表示するかは**未決**（7章）。

### 4-5. 人を見つけた後のつながり方
- **A：** 本人がプロフィールに連絡先を載せていれば、見た人が自分で外部（LINE 等）から連絡する。
- **C：** 連絡先がない人とは、共通のクラブに参加して会う。
- アプリ内で連絡をやりとりする機能は**作らない**。

### 4-6. 退会
- 退会したら、その人のデータは**すべて削除**する（プロフィール、属性、出没スポット、連絡先、所属）。
- その人がクラブの管理者だった場合は、退会の前に**そのクラブのメンバーの中から新しい管理者を決める**。新しい管理者が決まるまで退会は完了しない。
- 管理者以外にメンバーがいない場合は、**クラブも一緒に削除する**。
- 未成年のメンバーも新しい管理者になれる。

### 4-7. 運営（管理画面）
- 運営は、クラブとプロフィールを**非表示・削除**できる。
- 運営は、利用者に**未成年マーク**を付け外しできる（当面の暫定。正式な設定方法は招待の仕組みと一緒に決める）。
- 運営は、属性タグを追加・削除できる。

---

## 5. 未成年のルール

- 利用には**保護者の同意**が必要。同意の取り方は**未決**（招待の仕組みと一緒に決める）。
- 未成年には「未成年マーク」を表示する。
- 未成年は次のとおり制限する。
  1. **大人の「似た人」「おすすめ」「近い場所」の検索結果に出てこない**
  2. **出没スポットを入力できない**（地区単位も含む。住んでいる地区は必須項目として持つ）
  3. **連絡先を入力できない**
  4. 表示名は**ニックネームのみ**
  5. 所属・参加できるのは「**未成年参加可**」のクラブだけ
- 「お酒好き」などの大人向けの属性タグについて、未成年向けの制限はしない。

---

## 6. 禁止事項・作らないもの

- 作らない：アプリ内チャット、DM、投稿、タイムライン、いいね、フォロー、通知の大量送信
- 作らない：個人の出没スポットの曜日・時間の入力欄
- 利用ルールとして禁止：個人のプロフィールでの商品・サービスの宣伝、勧誘（保険、不動産、ネットワークビジネス等）
- 許可：有料の教室やお店主催の集まりを、**クラブとして**掲載すること（「有料」表示あり）

## 7. 未決事項（Claude Code は勝手に決めないこと）

| # | 項目 | 現時点の扱い |
|---|---|---|
| 1 | 招待の仕組み（誰が招待できるか、招待の記録を残すか） | 現在のログイン方式を維持。後から追加できる作りにする |
| 2 | 未成年の登録方法と保護者同意の取り方 | 当面は運営が管理画面で未成年マークを付ける |
| 3 | 監査の担当と頻度、新規登録時に運営へ通知するか | 管理画面で非表示・削除ができる状態までにする |
| 4 | 「問題を報告」ボタンを付けるか | 作らない（決まったら追加） |
| 5 | クラブの二重登録対策（似た名前の確認表示） | 作らない（決まったら追加） |
| 6 | 個人の連絡先を載せられるのは管理者本人だけにするか／管理者を移す仕組み | 作らない（決まったら追加） |
| 7 | 未成年が管理者のクラブで、「連絡・参加の方法」に未成年個人の連絡先が入ることをどう防ぐか | 質問すること |
| 8 | マインドマップでの未成年の表示 | 質問すること |
| 9 | 公開時に用意するクラブの件数と集め先 | 実装には影響しない |
| 10 | 運営主体、成功の指標（つながった数の計測等） | 実装には影響しない。計測が決まったら追加 |

## 8. 進め方（依頼者と Claude Code の合意事項）

1. **現状把握**：コードを変えずに、今ある画面・保存しているデータ項目・ログイン方式・未完成の部分を説明する。
2. **差分表**：この仕様書と今のアプリの差分を表にする（項目／仕様／現状／差分の大きさ 大中小／作業量の目安）。仕様と矛盾する既存機能も挙げる。
3. **計画**：差分「大」から順に修正計画を出す。承認されるまでコードは変えない。
4. **1つずつ実装**：1機能ずつ実装し、確認手順を示す。確認が済んでから次へ進む。

### 優先順位の目安
1. 未成年の制限（5章）と、作らないものの削除（6章）——安全に関わるため最優先
2. クラブ中心の画面とクラブ項目（4-1）
3. プロフィール・出没スポット・属性タグ（4-2）
4. 似た人・近い場所（4-3）
5. マインドマップ（4-4）
6. 管理画面（4-7）、退会（4-6）
